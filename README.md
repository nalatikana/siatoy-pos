# Siatoy TCG · POS

ระบบขายหน้าร้านและจัดการสต๊อกสำหรับร้านการ์ดสะสมเสี่ยทอย TCG
ยกมาจากเดโม `reference/Siatoy-TCG-POS-Demo.html` (ไฟล์เดียว ข้อมูลไม่ถูกบันทึก)
ให้กลายเป็นระบบใช้จริงที่หน้าร้านกับบูธงานใช้พร้อมกันได้ และขายต่อได้ตอนเน็ตหลุด

## โครงที่เลือกใช้

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| หน้าเว็บ | HTML + ES module ล้วน **ไม่มีขั้นตอน build** | ต่อยอดจากโค้ดเดโมได้ตรง ๆ ไม่ต้องลง node_modules หลายหมื่นไฟล์ในโฟลเดอร์ที่ซิงก์ OneDrive อยู่ |
| ไลบรารีภายนอก | วางไว้ใน `public/vendor/` เป็นไฟล์ในโปรเจกต์ | ตอนออฟไลน์ต้องไม่มีอะไรต้องโหลดจากเน็ต |
| ฐานข้อมูล | Supabase (PostgreSQL + Auth + Storage) | ฟรีในช่วงเริ่ม มีระบบสิทธิ์ระดับแถวในตัว |
| ข้อมูลในเครื่อง | IndexedDB | เก็บสินค้า ราคา และคิวบิลที่ยังส่งไม่สำเร็จ |
| โฮสต์ | หน้าเว็บเป็นไฟล์นิ่ง วางที่ไหนก็ได้ | ไม่มี build ก็ไม่มีอะไรพัง |

## โครงโฟลเดอร์

```
db/         migration ของฐานข้อมูล  รันตามลำดับเลข
src/        โค้ดแอป  (pages = หน้าจอ, lib = ตรรกะ, ui = ส่วนประกอบร่วม)
public/     ไฟล์นิ่ง  โลโก้ ฟอนต์ ไลบรารี
docs/       บันทึกการตัดสินใจ
reference/  เดโมตั้งต้นและโลโก้  ไว้เทียบ ไม่ใช่โค้ดที่รัน
```

## รัน migration

เปิด Supabase → SQL Editor → วางเนื้อไฟล์ `db/001_schema.sql` แล้วกด Run
(หรือถ้าติดตั้ง Supabase CLI แล้วใช้ `supabase db push`)

สคีมาถูกทดสอบกับ PostgreSQL 16 จริงแล้ว ทั้งกรณีบิลซ้ำจากเครื่องออฟไลน์
การยกเลิกบิลแล้วคืนของ และการกันแก้สมุดเดินของย้อนหลัง

## กติกาที่ห้ามพัง

1. **สต๊อกอ่านจาก `stock_moves` เท่านั้น** ห้ามมีช่อง "คงเหลือ" ที่เขียนทับได้
2. **บิลเก็บราคาและต้นทุน ณ วันขาย** ไว้ในบรรทัดบิล ห้ามคำนวณย้อนหลังจากราคาปัจจุบัน
3. **ต้นทุนอยู่ใน `product_costs` / `sale_item_costs`** ซึ่ง RLS ปิดไม่ให้พนักงานอ่าน
   ห้ามย้ายกลับไปไว้ในตารางเดียวกับสินค้า
4. **รหัสบิลและ id สร้างจากเครื่องขาย** ส่งขึ้นเซิร์ฟเวอร์ด้วย `on conflict do nothing` เสมอ
