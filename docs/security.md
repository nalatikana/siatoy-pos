# ความปลอดภัยของระบบ

## ภัยที่ระบบนี้ออกแบบมารับ

ร้านการ์ดไม่ได้เจอแฮกเกอร์เจาะระบบ แต่เจอเรื่องพวกนี้

| เรื่องที่เกิดจริง | ระบบรับมือยังไง |
|---|---|
| เครื่องหน้าเคาน์เตอร์ค้างล็อกอินเป็นเจ้าของ พนักงานเปิดดูต้นทุนได้ | ล็อกหน้าจอด้วย PIN และล็อกเองเมื่อไม่ได้แตะเครื่อง |
| พนักงานลาออกแล้วยังล็อกอินจากมือถือตัวเองได้ | เจ้าของปิดใช้งานหรือลบบัญชีได้ทันทีจากในแอป |
| ใช้รหัสเดียวกันทั้งร้าน จนตรวจไม่ได้ว่าใครทำอะไร | บัญชีแยกรายคน ทุกบิลและทุกส่วนลดผูกกับชื่อคนทำ |
| iPad หายที่งานอีเวนต์ทั้งที่ยังล็อกอินค้าง | PIN ล็อกจอ และเจ้าของลบบัญชีนั้นทิ้งได้ทันที |
| พนักงานเห็นต้นทุนและกำไร | ต้นทุนอยู่คนละตาราง ไม่ถูกส่งมาที่เครื่องพนักงานเลย |
| ใครก็ได้เอา anon key ไปสมัครบัญชีเองแล้วอ่านยอดขาย | **ต้องปิดการสมัครเองใน Supabase ด้วยมือ — ดูด้านล่าง** |

## สิ่งที่ต้องตั้งใน Supabase ด้วยตัวเอง

**1. ปิดการสมัครบัญชีเอง — สำคัญที่สุด**

Authentication → Sign In / Providers → ปิด **Allow new users to sign up**

ถ้าไม่ปิด ใครที่เปิดหน้าเว็บแล้วดูโค้ดจะเอา anon key ไปสมัครบัญชีเองได้
แล้วเข้ามาอ่านยอดขายและสต๊อกทั้งร้าน (อ่านต้นทุนไม่ได้ แต่แค่นี้ก็ไม่ควรให้เห็น)
บัญชีทั้งหมดต้องถูกสร้างโดยเจ้าของร้านผ่านหน้าผู้ใช้งานเท่านั้น

**2. เปิดตรวจรหัสผ่านที่เคยรั่วไหล**

Authentication → Policies → เปิด **Leaked password protection**
Supabase จะเทียบกับฐานรหัสผ่านที่เคยหลุดในอินเทอร์เน็ต แล้วไม่ให้ตั้งรหัสนั้น

**3. ตั้งความยาวรหัสผ่านขั้นต่ำ** อย่างน้อย 10 ตัว ที่หน้าเดียวกัน

## ที่ระบบทำให้แล้ว

- **PIN ล็อกหน้าจอ** แต่ละคนตั้ง PIN ของตัวเอง เก็บเป็นค่าที่ย้อนกลับไม่ได้
  (PBKDF2 สองแสนรอบ พร้อมค่าสุ่มประจำคน) และอยู่ในตารางที่แต่ละคนอ่านได้เฉพาะแถวของตัวเอง
  แม้แต่เจ้าของร้านก็อ่าน PIN ของพนักงานไม่ได้
- **ล็อกอัตโนมัติ** เมื่อไม่ได้แตะเครื่องตามเวลาที่ตั้งไว้ ค่าเริ่มต้น 5 นาที
- **ใส่ PIN ผิด 5 ครั้งติด** ต้องรอ 30 วินาที
- **ประวัติการเข้าใช้งาน** เข้าระบบ ออกจากระบบ ล็อก ปลดล็อก และใส่ PIN ผิด
  บันทึกพร้อมเครื่องและเวลา แก้หรือลบย้อนหลังไม่ได้แม้แต่เจ้าของร้าน เก็บ 180 วัน
- **ยืนยันตัวตนสองชั้น** สำหรับบัญชีเจ้าของร้าน ใช้แอปยืนยันตัวตนในมือถือ
- **สิทธิ์บังคับที่ฐานข้อมูล** ไม่ใช่การซ่อนปุ่ม พนักงานยิงคำสั่งตรงไปที่ฐานข้อมูลก็ยังอ่านต้นทุนไม่ได้
- **คีย์ระดับผู้ดูแลไม่เคยอยู่ในหน้าเว็บ** อยู่แต่ในฟังก์ชันฝั่งเซิร์ฟเวอร์

## เรื่องโฮสต์

โฮสต์ไม่มีผลกับความปลอดภัยของการล็อกอิน เพราะการล็อกอินเกิดที่ Supabase ไม่ใช่ที่โฮสต์
แต่การย้ายโฮสต์มีประโยชน์อื่น

| | GitHub Pages (ตอนนี้) | Cloudflare Pages | Vercel |
|---|---|---|---|
| ค่าใช้จ่าย | ฟรี | ฟรี | ฟรีเฉพาะ Hobby ซึ่ง**ห้ามใช้เชิงพาณิชย์** |
| repo เป็น private ได้ | ต้องเสียเงินขึ้น Pro | ได้ | ได้ |
| ตั้ง security header เองได้ | **ไม่ได้** | ได้ (ไฟล์ `_headers`) | ได้ |
| โดเมนของร้าน | ได้ | ได้ | ได้ |

ระบบ POS ของร้านที่ขายของจริงถือเป็นการใช้เชิงพาณิชย์
ถ้าจะย้ายเพื่อให้ repo เป็น private และตั้ง security header ได้ **Cloudflare Pages เหมาะกว่า**

ยังไม่ย้ายก็ไม่เป็นไร เพราะสิ่งที่อยู่ใน repo คือโค้ดกับ anon key ซึ่งเปิดเผยได้อยู่แล้ว
ข้อมูลขายทั้งหมดอยู่ในฐานข้อมูลที่ต้องล็อกอินถึงจะเข้าถึงได้

## ที่ยังไม่ได้ทดสอบ

**ยืนยันตัวตนสองชั้นยังไม่ได้ทดสอบกับ Supabase จริง** เพราะยังสร้างโปรเจกต์ไม่ได้
โค้ดเขียนครบแล้วและถูกกันไม่ให้พังเวลายังไม่ได้ต่อฐานข้อมูล
แต่ต้องลองเปิดใช้งานจริงหนึ่งรอบก่อนส่งมอบ ส่วน PIN ล็อกจอกับประวัติการเข้าใช้งาน
ทดสอบในเบราว์เซอร์จริงแล้ว
