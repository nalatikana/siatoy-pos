# บันทึกการตัดสินใจ

## 2026-08-29 · เลือกโครงระบบ
- web app + เซิร์ฟเวอร์กลางบนคลาวด์สำเร็จรูป งบเริ่มต้นต่ำ
- ต้องขายต่อได้ตอนเน็ตหลุด (ใช้ตอนออกบูธ) → เครื่องขายเก็บข้อมูลในเครื่องและตั้งรหัสบิลเอง
- ขอบเขตยึดตามเดโมทั้ง 13 หน้า ทยอยเปิดเป็น 4 เฟส
- เผื่อช่อง VAT ไว้ในสคีมา แต่ตั้งค่าเริ่มต้นเป็น 0 (ร้านยังไม่จด)

## 2026-08-29 · ไม่ใช้ขั้นตอน build
โปรเจกต์อยู่ในโฟลเดอร์ที่ OneDrive ซิงก์อยู่ การมี `node_modules` หลายหมื่นไฟล์
จะทำให้เครื่องอืดและซิงก์ไม่จบ ประกอบกับโค้ดเดโมเป็น JavaScript ล้วนอยู่แล้ว
จึงเลือกเขียนเป็น ES module ที่เบราว์เซอร์รันได้ตรง ๆ และเก็บไลบรารีที่ใช้
ไว้ในโปรเจกต์เอง ซึ่งจำเป็นอยู่แล้วสำหรับการทำงานตอนออฟไลน์

## 2026-08-29 · ต้นทุนแยกตาราง
สิทธิ์ในเดโมเป็นแค่การซ่อนด้วย CSS ต้นทุนยังถูกส่งไปถึงเครื่องพนักงาน
แก้ด้วยการย้ายต้นทุนออกไปเป็น `product_costs` และ `sale_item_costs`
แล้วปิดด้วย RLS ให้เฉพาะหัวหน้างานขึ้นไปอ่านได้ ข้อมูลจึงไม่เคยออกจากเซิร์ฟเวอร์
มาถึงเครื่องพนักงานตั้งแต่แรก

## 2026-08-29 · สมุดเดินของใช้ trigger ไม่ใช่ rule
เดิมกันการแก้ย้อนหลังด้วย `create rule ... do instead nothing` แต่ทดสอบแล้วพบว่า
ตารางที่มี rule แบบ update จะใช้ `insert ... on conflict do nothing` ไม่ได้
ซึ่งเป็นคำสั่งที่เครื่องออฟไลน์ต้องใช้ตอนส่งบิลซ้ำ จึงเปลี่ยนเป็น trigger ที่โยน error แทน
